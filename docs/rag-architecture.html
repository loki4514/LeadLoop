RAG = Retrieval-Augmented Generation Stack: FastAPI · RQ · Postgres+pgvector · Gemini

The pipeline — five boxes, in order

file → markdown → chunks → embeddings (vectors) → pgvector ⇄ similarity search
  1. 1

    Extract → markdown

    A PDF, Word, Excel, or text file comes in. MarkItDown turns any of them into one plain-markdown string. Every later step works on markdown, so it never cares what the original was.

    File
    app/ingestion/extract.py
    Decision
    Use MarkItDown as the universal "any file → text" front door.
    Watch
    .docx came in as one giant line — converters flatten newlines. That's why chunking can't rely on line breaks.
  2. 2

    Chunk it

    One big document is useless for search — you'd get back the whole file. We split it at markdown headings so each FAQ question becomes its own self-contained piece. Your 1-blob doc became 22 clean chunks.

    File
    app/ingestion/chunking.py
    Decision
    Heading-aware splitting, with a token-window fallback for huge sections.
    Watch
    Chunks too big → search returns vague whole-doc matches. Too small → answers lose context.
  3. 3

    Embed → vectors

    Each chunk goes to Gemini, which returns a vector — a list of 768 numbers that captures the chunk's meaning. This is the step people skip in their head: text doesn't go into the database, its vector does.

    File
    app/embeddings/ (pluggable: base · gemini · factory)
    Decision
    Provider is swappable — Gemini today, OpenAI/others later, behind one interface.
    Watch
    Wrong model name → 404. Wrong vector size → broken inserts. Both bit us this session.
  4. 4

    Store in pgvector

    Chunk text + its vector are saved together in Postgres, in a special vector(768) column. An HNSW index makes "find the nearest vectors" fast and accurate.

    File
    app/models/document.py · alembic/versions/
    Decision
    One active model at a time; switching models means re-embedding everything.
    Watch
    Wrong index (ivfflat) returned zero results with no error — the scariest kind of bug. Fixed by switching to HNSW.
  5. 5

    Search (retrieve)

    A question gets embedded the same way, then Postgres finds the closest chunks by cosine distance. That's the retriever — it hands back the most relevant pieces, ranked by score.

    File
    app/retrieval/search.py · API in routes/documents.py
    Decision
    Return top-K chunks with a similarity score, ready to feed an LLM.
    Watch
    Vectors must be normalized or cosine scores are meaningless — handled in the Gemini provider.

Steps 1–4 happen once per upload, in the background worker. Step 5 happens every time someone asks a question. That split is worth remembering.

The decisions you actually made

These weren't typing. They were judgment calls — and you made every one. This is what ownership looks like.

The questionYour callWhy it matters
Which embedding model? Pluggable Gemini now, swap to OpenAI/DeepSeek later without rewriting the pipeline.
What happens when you switch models? Re-embed all Simplest, cleanest schema. The cost: a re-embed run on switch — fine if rare.
Which vector index? HNSW Correct from the very first row; no fragile tuning. ivfflat silently returned nothing.
How to split documents? By heading Each FAQ answer is its own chunk → search returns the precise answer, not the whole file.
Where do files live? Local volume Simplest to start; swap to S3 when you need it. A deliberate "not yet," not an oversight.

How it breaks — every bug this session was a decision, not a typo

404 — model not found
Asked for text-embedding-004; your key only exposes gemini-embedding-001. → Use the right model name.
Search returns nothing (no error)
The ivfflat index probes one cluster of 100; with little data it finds an empty one. → HNSW index.
Whole document comes back as one result
Chunks were too coarse (one 538-word blob). → Heading-aware chunking, 22 focused pieces.
Vector won't insert
Model returned 3072 numbers; the column expects 768. → Pin the output dimension to match.

See the pattern? Not one was about syntax. Every one was a name, a size, a structure, a choice. That's the layer you keep. The typing is the layer you hand off.
